# IEUM Chain v1.0.11.0 — EVM 탑재 (A1·A2)

## 버전과 포함 변경

- Cargo 버전 `1.0.11-0`, 표시 버전과 태그 `1.0.11.0`, `v1.0.11.0`
- revm 43(Prague 규칙)으로 계약 배포·호출을 실행합니다. 프로토콜 v4이며 **기본은 꺼져 있습니다.**
- Chain ID와 genesis는 바뀌지 않습니다. 계약이 하나도 없으면 상태 해시도 이전 버전과 같습니다.

## 실행 규칙

| 항목 | 규칙 |
|---|---|
| 거래 형식 | EIP-155 legacy raw 거래만 받습니다. 배포는 `to`가 빈 거래입니다. |
| 배포 권한 | 누구나 배포할 수 있고, 가스비로 스팸을 막습니다. |
| 가스 | 블록당 gasLimit 합계는 30,000,000까지입니다. 수수료는 실제 사용 가스 × gasPrice입니다. |
| 수수료 분배 | 기존 송금과 같이 블록 생산자 80%, 재단 20%입니다. 소각은 없습니다. |
| 실패 거래 | revert·halt된 거래도 블록에 남습니다. 수수료와 nonce만 반영하고 상태는 되돌립니다. |
| 블록 환경 | `block.timestamp`는 블록 시각, `prevrandao`는 0, `COINBASE`는 생산자 검증자 ID에서 만든 20바이트 주소, `BLOCKHASH`는 0입니다. |
| 송금 → 계약 | raw 송금이 코드가 있는 주소로 가면 계약의 `receive()`를 실행합니다. IEUM 자체 서명 송금은 잔액만 옮깁니다. |

## 활성화 절차

1. 4노드를 모두 1.0.11.0으로 업데이트하고, 높이가 같고 경고가 없는지 확인합니다.
2. 현재 높이보다 충분히 뒤(예: 현재 + 20)를 활성 높이로 정합니다. 이 체인은 거래가 있을 때만 블록을 만듭니다.
3. 4노드의 `config/upgrades.json`에 **같은 값**을 추가하고 노드를 차례로 재시작합니다.

```json
{
  "upgrades": [
    { "name": "staking-v1", "activation_height": 23, "protocol_version": 3 },
    { "name": "evm-v1", "activation_height": 130, "protocol_version": 4 }
  ]
}
```

활성 높이 전에는 RPC가 계약 거래를 거부하고, 검증자도 계약 거래가 든 블록을 거부합니다.

## 확인 결과

- OpenZeppelin ERC-20·ERC-721 배포, 전송, `ownerOf`, revert, 계약 안 CREATE, `receive()`·출금 테스트를 통과했습니다.
- genesis 재생과 snapshot 복원의 상태 해시가 같고, 블록 가스 한도와 제안자 거래 선별을 확인했습니다.
- 실제 메인넷 원장(높이 106)을 genesis부터, 그리고 h82 체크포인트부터 재생해 노드의 상태 루트와 같음을 확인했습니다.
- 4-process BFT 네트워크 테스트(송금, 재시작, 재합류)를 통과했습니다.

## 알려진 제한

- 월별 백업으로 넘어간 블록의 계약 영수증·로그는 snapshot에 담지 않습니다. 오래된 로그 조회가 필요하면 A3에서 영수증 보관소를 추가합니다.
- `eth_call`의 `blockTag`는 무시하고 최신 확정 상태에서 실행합니다.
