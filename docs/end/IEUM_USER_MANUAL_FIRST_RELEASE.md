# IEUM 1차 완료본 사용자 매뉴얼

기준일: 2026-08-04  
대상: IEUM Core v0.21.1 계열 기능 테스트넷, IEUM Wallet v0.0.9.1 계열

## 1. IEUM은 무엇인가요?

IEUM은 여러 컴퓨터가 거래 기록을 함께 확인하고 보관하는 블록체인입니다. 한 회사의 서버 한 대가 기록을 마음대로 바꾸는 방식이 아니라, 여러 검증 노드가 같은 거래에 동의한 뒤 기록을 확정합니다.

현재 버전은 **1차 기능 시험용**입니다. 송금과 네트워크 시험은 할 수 있지만 실제 큰돈이나 중요한 개인정보를 보관하는 메인넷 완성본은 아닙니다.

## 2. 지금 할 수 있는 일

- 새 지갑 만들기 또는 12개 복구 단어로 지갑 복원
- IEUM 주소와 QR 확인
- 잔액 확인, IEUM 보내기, 거래 결과 확인
- 친구 주소록과 그룹별 순차 송금
- 로컬 노드의 네트워크·동기화 상태 확인
- 시험용 암호화 채팅과 음성·영상 통화
- Windows, Ubuntu, Android 시험 빌드 사용

아직 할 수 없거나 정식 사용하면 안 되는 일:

- WASM 스마트 계약 배포·실행
- 검증이 끝난 AAH↔IEUM 탈중앙 교환
- 메인넷 수준의 광고 보상 실지급
- 실자산 대량 보관
- 원격 키보드·마우스 제어

## 3. 꼭 지켜야 할 안전 수칙

1. 12개 복구 단어와 개인키를 누구에게도 보내지 마세요.
2. 복구 단어를 채팅, 이메일, 클라우드, 화면 캡처로 보관하지 마세요.
3. 운영자가 요청해도 복구 단어나 개인키를 알려주면 안 됩니다.
4. 처음 보내는 주소에는 아주 적은 금액을 먼저 시험하세요.
5. 주소 앞뒤 몇 글자만 보지 말고 전체 주소 또는 QR을 다시 확인하세요.
6. 현재는 테스트넷이므로 잃어도 문제가 없는 시험 자산만 사용하세요.

복구 단어를 잃으면 지갑을 되찾지 못할 수 있습니다. 반대로 다른 사람이 복구 단어를 알면 비밀번호 없이도 다른 기기에서 지갑을 복원할 수 있습니다.

## 4. 가장 쉬운 사용 방법 — IEUM Wallet

### 처음 시작

1. 운영체제에 맞는 설치 파일을 받습니다.
2. 코드 서명과 배포 출처를 확인합니다. 시험 빌드는 운영체제 경고가 나올 수 있으므로 출처가 확실하지 않으면 설치하지 마세요.
3. `새 지갑 만들기`를 선택합니다.
4. 표시되는 12개 복구 단어를 종이에 정확한 순서로 적습니다.
5. 지갑 잠금 비밀번호를 정합니다.
6. 네트워크 연결과 동기화 완료 표시를 확인합니다.

기존 지갑은 `지갑 복원`에서 12개 복구 단어 또는 지원되는 개인키를 사용합니다. 화면을 다른 사람이 볼 수 없는 곳에서 입력하세요.

### IEUM 받기

1. `받기`를 누릅니다.
2. 내 주소 또는 QR을 보내는 사람에게 전달합니다.
3. 주소는 공개해도 되지만 복구 단어와 개인키는 절대 전달하지 않습니다.
4. 상대가 보냈다고 말해도 지갑에서 확정 상태를 직접 확인합니다.

### IEUM 보내기

1. `보내기`를 누릅니다.
2. 받는 주소와 금액을 입력합니다.
3. 수수료와 최종 받는 주소를 다시 확인합니다.
4. 처음 보내는 주소라면 소액을 먼저 보냅니다.
5. 비밀번호로 잠금을 풀고 서명합니다.
6. 전송됨과 확정됨은 다를 수 있으므로 최종 확정을 기다립니다.

거래를 한 번 확정하면 일반 송금처럼 취소 버튼으로 되돌릴 수 없습니다.

## 5. 연결 문제가 생겼을 때

지갑 화면에 `연결 확인 필요`가 나오면 다음 순서로 봅니다.

1. 인터넷 연결을 확인합니다.
2. IEUM 노드가 실행 중인지 확인합니다.
3. 기본 RPC 주소가 `http://127.0.0.1:8989`인지 확인합니다.
4. 노드의 동기화가 끝났는지 확인합니다.
5. 계속 실패하면 지갑과 노드 버전이 서로 맞는지 확인합니다.

`127.0.0.1`은 내 컴퓨터를 뜻합니다. 다른 컴퓨터의 노드에 연결하려면 운영자가 제공한 안전한 HTTPS RPC 주소가 필요합니다. 알 수 없는 사람이 준 RPC 주소는 사용하지 마세요.

## 6. 일반 PC에서 노드 실행

실행 파일이 있는 폴더에서 다음처럼 실행합니다.

Ubuntu:

```bash
./ieum-chain
```

Windows PowerShell:

```powershell
.\ieum-chain.exe
```

일반 사용자는 `server` 옵션을 붙이지 않아도 됩니다. 프로그램은 필요한 파일을 자동으로 만들고 기본 운영 노드에 연결을 시도합니다.

프로그램을 처음 실행할 때 만들어지는 키와 `data` 폴더를 다른 PC의 것과 섞지 마세요.

## 7. 운영 서버 관리자용 간단 안내

외부 노드가 접속하는 운영 서버는 다음처럼 실행합니다.

```bash
./ieum-chain server
```

기본 포트:

| 용도 | 주소/포트 | 공개 여부 |
|---|---|---|
| 다른 노드 연결 | UDP 7001 | 방화벽과 공유기에서 허용 |
| 지갑·관리 RPC | 127.0.0.1:8989 | 인터넷에 직접 공개 금지 |

Cloudflare의 일반 웹 프록시는 IEUM P2P용 UDP 7001을 대신 전달하지 않습니다. P2P 도메인은 DNS only로 설정합니다.

서비스 상태 확인:

```bash
sudo systemctl status ieum-chain --no-pager
sudo journalctl -u ieum-chain -f
```

노드 검사:

```bash
cd /opt/ieum-chain
./ieum-chain node verify
./ieum-chain node doctor
```

## 8. 반드시 백업할 항목

운영 노드는 다음을 함께 백업합니다.

```text
config/validator.key
data/server.node.key
data/reward.key
data/ledger/
config/validators.json
config/events.json
config/upgrades.json
config/bootstrap.json
```

백업할 때는 가능하면 서비스를 먼저 멈춥니다. 개인키 파일을 Git, 메신저, 공개 클라우드 폴더에 올리지 마세요.

키나 원장이 사라졌다고 새 키를 바로 만들면 다른 노드로 인식될 수 있습니다. 먼저 백업을 복원하고 `node verify`로 확인합니다.

## 9. 업데이트

설치본에 자동 업데이트 설정이 있으면 노드는 다음을 확인한 뒤 새 실행 파일을 설치합니다.

- 공식 릴리스 서명
- 파일 SHA-256 체크섬
- 내 운영체제에 맞는 파일인지

검증자 서버 여러 대를 한꺼번에 업데이트하지 마세요. 한 대씩 업데이트하고 노드 연결·동기화·블록 확정을 확인한 뒤 다음 서버를 진행합니다.

합의 규칙이 바뀌는 버전은 단순 자동 업데이트만으로 적용하면 안 됩니다. 모든 검증자가 같은 활성 블록 높이를 미리 합의해야 합니다.

## 10. 사고가 발생했을 때

확정된 원장의 파일이나 SQLite 행을 직접 지우지 마세요. 특정 서버 한 대만 과거 상태로 돌리는 것도 금지합니다.

IEUM은 사고를 두 가지로 나눕니다.

- 거래 단위 복구: 피해 거래가 명확할 때 원본 거래를 남기고 보상 기록을 새로 추가
- 체크포인트 롤백: 원장 전체 손상이나 합의 오류처럼 매우 큰 사고일 때만 사용

두 경우 모두 여러 검증자의 강한 승인이 필요합니다. 관리자가 혼자 결정해서 거래를 삭제하거나 잔액을 고치면 안 됩니다.

사고 시 순서:

1. 모든 관련 서버의 현재 원장과 키를 별도 백업
2. 대상 거래·블록 높이·블록 해시·상태 해시 기록
3. 검증자들의 동일한 복구 계획 승인
4. 시험망에서 복구 결과와 총공급량 확인
5. 한 대씩 운영 재개 후 서로 같은 상태인지 확인

## 11. 채팅과 영상 통화

채팅 내용과 영상은 블록체인 원장에 저장하지 않습니다. 지갑은 별도의 암호화 통신 기능을 사용합니다.

- 상대의 지갑 주소와 PeerId를 정확히 확인하세요.
- 채팅방 보안 키는 같은 채팅방 안에서 보내지 마세요.
- 카메라와 마이크 권한은 통화할 때만 허용하세요.
- 통화가 끝나면 권한과 감사 기록을 확인하세요.
- 원격 제어 기능은 보안 감사 전에는 사용하지 않습니다.

## 12. WASM 스마트 계약은 언제 사용할 수 있나요?

IEUM은 EVM 대신 가볍고 제한된 WebAssembly(WASM) 계약을 사용할 계획입니다. 하지만 현재 1차 완료본에는 WASM 실행 기능이 없습니다.

앞으로 지원되면 사용자는 개발자가 만든 계약의 내용을 지갑에서 확인하고 서명하게 됩니다. 계약 호출 전 지갑은 최소한 다음을 쉬운 말로 보여줘야 합니다.

- 어떤 계약을 실행하는지
- 얼마의 IEUM을 보내는지
- 예상 수수료가 얼마인지
- 내 잔액이나 권한이 어떻게 바뀌는지
- 실패할 경우 어떤 수수료가 드는지

이 표시가 없는 임의 계약에는 서명하지 마세요.

## 13. 현재 버전의 정확한 의미

| 사용 목적 | 판단 |
|---|---|
| 학습과 개발 | 사용 가능 |
| 소액 기능 시험 | 사용 가능 |
| 사설 테스트넷 | 사용 가능 |
| 제한된 파일럿 | 운영 점검 후 가능 |
| 큰 금액 보관 | 권장하지 않음 |
| 공개 실자산 메인넷 | 아직 아님 |
| WASM 계약 | 아직 지원하지 않음 |

문제가 생기면 버전, 운영체제, 오류 화면, 발생 시각, 거래 해시를 기록하세요. 복구 단어와 개인키는 문제 해결 자료에 절대 포함하지 마세요.
