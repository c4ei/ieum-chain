# IEUM Chain 0.21.8 변경 내역

작성일: 2026-08-05

## 이번 버전에서 완료

- `ieum-chain server --git_action_test`를 GitHub Actions 전용 격리 모드로 추가한다.
- `--git_action_test`에서는 P2P를 `127.0.0.1`에만 바인딩하고 mDNS 주소 학습,
  AutoNAT 서버 등록, 릴레이 예약과 운영 bootstrap 접속을 비활성화한다.
- `--git_action_test`에서만 고정 개발 검증자 키와 짧은 BFT 제한 시간을 자동 적용한다.
  일반 실행은 기존 운영 P2P, 키, 제한 시간 설정을 그대로 사용한다.
- 4프로세스 CI를 매 실행마다 새 임시 원장을 사용하는 일회용 개발망으로 유지한다.
- 운영 `config/genesis.json`은 변경하지 않고 `--git_action_test` 실행 중에만
  고정 개인키와 일치하는 개발 테스트 계정 4개에 각각 1 IEUM을 배정한다.
- 네 노드 모두에서 네 테스트 계정이 각각 최소 1 IEUM을 보유했는지 송금 전에 확인한다.
- 첫 번째 테스트 계정에서 두 번째 테스트 계정으로 정확히 0.1 IEUM을 전송해 실제 입금을 확인한다.
- `eth_sendTransaction`이 HTTP 200이어도 JSON-RPC `error`가 있으면 즉시 실패한다.
- 거래 해시가 반환됐는지 확인한 뒤 네 노드의 블록 높이, 상태 루트와 수신 잔액
  `0.1 IEUM`이 모두 일치해야 성공한다.
- 합의 높이는 정확히 1로 고정하지 않고 네 노드가 같은 1 이상의 높이인지 검사해
  정상적으로 다음 라운드가 진행된 경우의 오탐을 없앤다.

## 키 파일 이름과 호환 이전

| 역할 | 이전 경로 | 0.21.8 기본 경로 |
|---|---|---|
| P2P 노드 식별 | `data/server.node.key` | `data/keys/p2p_identity.key` |
| BFT 합의 서명 | `config/validator.key` | `data/keys/consensus_signing.key` |
| 노드 보상 등록 서명 | `data/reward.key` | `data/keys/node_reward_signing.key` |

기존 설치에서 새 경로가 없고 이전 파일만 있으면 시작 시 파일 자체를 이동하고
개인 파일 권한을 다시 적용한다. 키 내용은 바뀌지 않으므로 PeerId, 검증자 공개키와
기존 보상 주소가 유지된다. 이전 경로와 새 경로가 모두 있으면 자동 덮어쓰지 않는다.

## 다음 큰 버전에서 추가할 작업

다음 작업은 단순 파일명 변경이 아니라 자산 개인키 형식과 복구 절차를 바꾸므로
호환성 검토와 마이그레이션이 필요한 `0.22.0` 범위로 분리한다.

- 자산을 보유하는 별도 `data/keys/node_wallet.keystore` 도입
- 최초 운영 실행에서 비밀번호 2회 입력, Argon2id 기반 KDF와 인증 암호화 적용
- 서비스 실행용 비대화형 암호 전달 방식과 OS secret store 연동
- 복구용 BIP-39 니모닉 또는 암호화 백업 파일의 1회 확인 절차
- 개발망에서만 빈 암호와 고정 테스트 지갑 허용, 운영망에서는 빈 암호 거부
- 노드 보상 주소를 실제 자산 지갑과 연결하고 확정 블록의 입금·잔액 RPC 제공
- 기존 Ed25519 보상 등록 서명과 secp256k1 자산 주소를 안전하게 연결하는 프로토콜 전환

`node_reward_signing.key`는 보상 주소 소유권 등록에 쓰는 기존 합의용 키이며,
향후 `node_wallet.keystore`를 구현한 것처럼 오해하면 안 된다.

## 릴리스 순서

1. Chain Actions 전체 성공을 확인한다.
2. 성공한 커밋에 `v0.21.7` 태그를 생성하고 푸시한다.
3. Wallet 0.0.10.6 Actions를 `core_ref=v0.21.7`로 실행한다.
