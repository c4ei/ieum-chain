# IEUM Chain v0.21.5

- Windows MSVC에서 SQLite를 정적으로 연결해 `__imp_sqlite3_*` LNK2019 오류를 수정했다.
- Normal relay 보상에 최소 1시간 연속 가동 검증을 추가했다.
- 노드 보상 총량을 210,000,000 IEUM(2억 1천만 개)로 고정했다.
- 현재 높이 0을 기준으로 높이 100과 `2026-08-10 00:00:00 KST`를 모두 충족한
  첫 확정 블록부터 보상 계산이 가능하도록 했다.
- 2040년 말까지 매년 50%씩 줄어드는 예산과 마지막 정수 잔여 정산을 구현했다.
- 최소 1시간 연속 가동과 서로 다른 검증 피어 3곳의 중계 확인을 요구한다.
- 일반 노드 1.0배, 메인 4노드 1.5배 가중치를 일일 예산 안에서 계산한다.
- 실제 전송 수수료의 20%가 기존 재단 주소로 들어가는 합의 규칙을 유지했다.
- 활성화 양쪽 조건, 연도별 예산 총합, 누적 2억 1천만 상한을 테스트한다.

## 운영 설정 파일

`src/node_emission.rs`에 한국어 주석과 함께 다음 값이 모여 있다.

- `REWARD_ACTIVATION_HEIGHT = 100`
- `REWARD_ACTIVATION_UNIX = 1786287600`
- `REWARD_END_UNIX`
- `TOTAL_NODE_EMISSION_IEUM = 210_000_000`
- `MAIN_NODE_WEIGHT_BPS = 15_000`
- `MAIN_NODE_PEER_IDS`

합의 상수이므로 운영 중 값을 바꿀 때는 파일만 서버마다 따로 고치면 안 된다. 새 체인
버전으로 올리고 4개 검증자를 같은 활성화 높이에서 업그레이드해야 한다.

## 남은 작업

- 운영 메인 4노드의 실제 PeerId를 `MAIN_NODE_PEER_IDS`에 입력한다. 비어 있으면 일반
  보상은 계산되지만 1.5배 우대 대상은 없다.
- 중계 영수증의 서명 전파를 BFT 확정 블록 시스템 이벤트에 연결한다.
- 누적 지급량을 SQLite·스냅샷·상태 해시에 저장하고 재시작 후에도 상한을 검증한다.
- 위 두 런타임 연결이 완료되기 전에는 계산 엔진이 실제 잔액을 발행하지 않는다.
- 4검증자 테스트넷에서 같은 영수증으로 동일 정산 결과와 상태 해시가 나오는지 검증한다.
